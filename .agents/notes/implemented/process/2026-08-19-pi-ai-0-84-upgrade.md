# Agent Note: pi-ai 0.84 upgrade absorption in llm-pi-ai

Status: implemented

English | [中文](2026-08-19-pi-ai-0-84-upgrade.zh.md)

## Problem

Z.ai coding plans ship GLM-5.3, which the pinned pi-ai 0.82.1 catalog predates, so DSH's model picker could not offer the model. Bumping to 0.84.2 fixes that, but the pin existed because the adapter deliberately re-derives its configuration surface from pi-ai's types: a bump is not a version-number edit but a round of drift absorption the build fails on until each change is classified.

## Decision

The pin moves to `^0.84.2` and every upstream change lands in one of the adapter's existing classification mechanisms rather than beside them:

- **Compat gates.** 0.84 adds `supportsFinishReason`, `chatTemplateArgs`, and `supportsThinkingTokenBudget` to `OpenAICompletionsCompat`, and `supportsAdditionalTools` to `OpenAIResponsesCompat`. 0.84.3 adds `thinkingTokenBudgetField` (offered — the field-spelling successor of the budget switch) and widens the chat-template placeholders with `thinking.budget` (offered); Anthropic's `allowedFallbackModels` stays withheld with the vendor-catalog family. The first three are offered — each is a wire correction a private gateway needs and nothing can infer from its URL, and `chatTemplateArgs` makes the `baseten` thinking format nameable exactly as `chatTemplateKwargs` made the two `chat-template` variants nameable. `supportsAdditionalTools` stays withheld with the deferred-tools family it belongs to. These follow [[2026-08-18-pi-ai-wire-compat-surface]], whose counts this note's numbers supersede.
- **StopReason union.** 0.84 widens `StopReason` with `pending` and `deferred`. Neither is reachable on a terminal event here — `pending` marks an in-flight message and `deferred` requires a deferred-response opt-in the adapter never makes — so `mapStopReason` maps both to `PI_AI_ERROR` failures rather than pretending they carry a result.
- **Abort classification.** 0.84 wraps `Models.streamSimple` in a lazy setup stage (auth resolution, lazy module load), and a request aborted before streaming starts fails inside that stage, which reports `stopReason: "error"` with the abort reason as the message — the correct `aborted` classification in the protocol implementation is never reached. `toStreamChunks` therefore takes the request's abort signal and maps an `error` event arriving on an aborted signal to an `aborted` finish, whatever pi-ai's own classification was. The signal is the caller's fact, so the check cannot misfire on a provider failure that merely coexists with a later abort.
- **Catalog entries.** The installed 0.84 catalog gives DeepSeek models a `low` thinking level and `maxTokensField: "max_tokens"`. Both are catalog data the adapter passes through verbatim; the tests that pinned 0.82.1's list and field follow the entries.

## Alternatives considered

**Withhold `baseten` as the 0.82.1-era patch did.** The rc.7 quick fix kept `baseten` out of the nameable formats because `chatTemplateArgs` did not exist. rc.8's compat surface already carries kwargs through profile fields; offering the args field is the same mechanism one step further, and withholding it would keep a shipped upstream format unreachable for no reason the surface itself endorses.

**Parse the abort out of pi-ai's error message.** The setup stage reports the abort as `stopReason: "error"` with the signal's reason stringified. Matching that text would bind classification to a message pi-ai does not contractually guarantee; the signal is.

**Map `pending` and `deferred` to a best-effort finish.** A turn that ended in either state has no assistant result to hand the loop; inventing an empty `stop` would turn an impossible state into a silent success instead of the failure diagnostic both mappings emit.

## Consequences

- `zai` and `zai-coding-cn` catalog routes offer `glm-5.3`; `baseten` endpoints become configurable through `chatTemplateArgs`; vLLM-style gateways can declare `supportsThinkingTokenBudget`.
- An abort before any provider byte arrives still yields `{kind: "aborted"}` on the harness seam, preserving the contract consumers see across the pi-ai bump.
- The web provider-directory snapshots follow the installed catalog; the 0.84 catalog's provider set needed no change beyond what the pinned MiniMax entry already shows.
- The next pi-ai release that adds a compat field, a thinking format, or a stop reason fails this adapter's build until it is classified here — that is the mechanism working, not a defect of the bump.
