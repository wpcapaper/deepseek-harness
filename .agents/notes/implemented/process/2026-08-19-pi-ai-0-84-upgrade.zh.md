# Agent Note: llm-pi-ai 对 pi-ai 0.84 升级的吸收

Status: implemented

[English](2026-08-19-pi-ai-0-84-upgrade.md) | 中文

## Problem

Z.ai coding plans 开始提供 GLM-5.3，而钉在 0.82.1 的 pi-ai catalog 早于该模型，DSH 的模型选择器因此无法提供它。升到 0.84.2 解决了这个问题，但这枚版本钉之所以存在，是因为适配器刻意从 pi-ai 的类型派生自己的配置面：一次版本提升不是改一行版本号，而是一轮漂移吸收——每一处上游变更未经分类，构建就会失败。

## Decision

版本钉移至 `^0.84.2`，每一处上游变更都落进适配器既有的分类机制，而不是落在机制旁边：

- **compat 门禁。** 0.84 给 `OpenAICompletionsCompat` 新增 `supportsFinishReason`、`chatTemplateArgs`、`supportsThinkingTokenBudget`，给 `OpenAIResponsesCompat` 新增 `supportsAdditionalTools`。前三者予以开放——它们各自都是私有网关所需的线上修正，且无法从 URL 推断；`chatTemplateArgs` 使 `baseten` 思考格式可命名，正如 `chatTemplateKwargs` 曾使两个 `chat-template` 变体可命名。`supportsAdditionalTools` 与它所属的 deferred-tools 家族一起保持扣留。这些分类遵循 [[2026-08-18-pi-ai-wire-compat-surface]]，其字段计数以本注记的数字为准。
- **StopReason 并集。** 0.84 为 `StopReason` 扩入 `pending` 与 `deferred`。二者在终止事件上均不可达——`pending` 标记仍在流中的消息，`deferred` 需要调用方选择启用延迟响应而适配器从不启用——因此 `mapStopReason` 把两者都映射为 `PI_AI_ERROR` 失败，而不是假装它们携带结果。
- **abort 分类。** 0.84 用惰性 setup 阶段（auth 解析、惰性模块加载）包起 `Models.streamSimple`，在流开始前被 abort 的请求在该阶段内失败，汇报的是 `stopReason: "error"`、消息为 abort 原因——协议实现里正确的 `aborted` 分类永远走不到。`toStreamChunks` 因此接收请求的 abort 信号，把到达时信号已 abort 的 `error` 事件映射为 `aborted` 终止，无论 pi-ai 自己的分类是什么。信号是调用方的事实，因此该检查不会把仅仅与稍后 abort 并存的提供方故障误判。
- **catalog 条目。** 0.84 已安装 catalog 给 DeepSeek 模型增加了 `low` 思考档位与 `maxTokensField: "max_tokens"`。两者都是适配器原样透传的 catalog 数据；钉住 0.82.1 列表与字段的测试跟随条目更新。

## Alternatives considered

**像 0.82.1 时代的补丁那样扣留 `baseten`。** rc.7 的快速修法把 `baseten` 挡在可命名格式之外，因为当时 `chatTemplateArgs` 还不存在。rc.8 的 compat 面已经通过 profile 字段承载 kwargs；开放 args 字段是同一机制再往前一步，扣留它只会让一个已随上游发布的格式继续不可达，而这一扣留没有任何该机制自身认可的依据。

**从 pi-ai 的错误消息里解析 abort。** setup 阶段把 abort 汇报为 `stopReason: "error"`，并把信号原因字符串化进消息。匹配这段文本会把分类绑定在 pi-ai 并未以契约保证的消息上；信号才是契约。

**把 `pending` 与 `deferred` 映射为尽力而为的终止。** 以这两种状态收尾的回合没有任何可交给循环的助手结果；虚构一个空的 `stop` 会把不可能状态变成静默成功，而不是两条映射各自发出的失败诊断。

## Consequences

- `zai` 与 `zai-coding-cn` catalog 路由提供 `glm-5.3`；`baseten` 端点经由 `chatTemplateArgs` 变为可配置；vLLM 式网关可以声明 `supportsThinkingTokenBudget`。
- 任何提供方字节到达之前的 abort 在 harness seam 上仍然产生 `{kind: "aborted"}`，在 pi-ai 版本提升前后维持消费者所见契约。
- Web 提供方目录快照跟随已安装 catalog；0.84 catalog 的提供方集合无需超出钉住的 MiniMax 条目已有的变化。
- 下一个新增 compat 字段、思考格式或 stop reason 的 pi-ai 发布，都会使本适配器构建失败，直到在这里完成分类——那是机制在起作用，不是这次升级的缺陷。
